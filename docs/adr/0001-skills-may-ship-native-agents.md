# Skills may ship native agents that the installer links

`deep-review` needs distinct reviewer roles with their own model, tool, and sandbox limits, and no harness lets a skill directory declare its own subagents: Codex reads `~/.codex/agents/`, Devin reads `~/.config/devin/agents/` (`%APPDATA%\devin\agents\` on Windows), and Claude Code reads `~/.claude/agents/`. We keep those native agent definitions inside the owning skill at `skills/<skill>/harnesses/<harness>/` and extend the repository installers with a generic step that links them into each selected harness's agent directory, with the same recognition, backup, and reconciliation rules as skills. Those agent files are generated, never hand-edited: a per-skill `harnesses/roles.toml` manifest plus the skill's reviewer bodies are the single source of truth, a generic generator writes every harness's file with one agent name shared across all harnesses, and `python scripts/check.py` fails when a generated file is stale. We rejected a top-level `harnesses/` tree, which splits one skill's ownership across the repository, and a Claude plugin, which would serve only one of the three harnesses.
